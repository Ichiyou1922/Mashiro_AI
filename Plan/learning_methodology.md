# 理解を中心とした学習法

## 原則

```
❌ AIに書いてもらう → 動いた → 終わり
✅ 理解する → 自分で書ける → 応用できる → 自分のもの
```

**内側からの情熱と喜びを大切にする。**
自分が理解できないものを「自分のもの」とは言わない。

---

## 1. 逆方向学習法

```
通常: 書く → 動く → 理解（するかも）
逆方向: 読む → 理解 → 自分で書く
```

### 具体的なステップ
1. 既存のコードを**読む**
2. 各行が「なぜそう書かれているか」を説明できるまで理解
3. 理解したら、**見ないで**同じものを書いてみる
4. 詰まったら「答え」を見る（写経ではなく確認）

---

## 2. AIを「教師」として使う

**代筆者ではなく、百科事典として使う。**

### 使い方の例

```
❌ 避けるべき使い方
"このコードを書いて"
"この機能を実装して"

✅ 推奨する使い方
"このコードの仕組みを説明して"
"なぜここでasyncを使うの？"
"この設計パターンの名前と意図は？"
"もし自分で書くなら、どこから始めるべき？"
"この概念を初心者に説明するように教えて"
```

---

## 3. 車輪の再発明（学習目的）

普通は「車輪の再発明をするな」と言われる。
でも学習目的なら**むしろやるべき**。

### 例

| 既存ライブラリ | 自分で実装してみる |
|----------------|-------------------|
| `json.loads()` | JSONパーサーを書く |
| `requests.get()` | ソケット通信を書く |
| WebSocketライブラリ | 自分でプロトコル実装 |
| LoRAの概念 | 行列演算を手で書く |

**理解したら、本番では既存ライブラリを使えばいい。**

---

## 4. 「説明できる」をゴールにする

### 理解のレベル

```
レベル1: 動く
レベル2: なぜ動くか説明できる ← 最低限ここ
レベル3: 別の方法でも書ける
レベル4: 他人に教えられる ← 理想
```

### 自分への質問

- 「この行を消したらどうなる？」
- 「この変数の型は何？」
- 「この関数の計算量は？」
- 「なぜこの設計にした？他の選択肢は？」
- 「これを5歳児に説明できるか？」

---

## 5. 写経ではなく「翻訳」

```
❌ 写経: コードをそのまま打ち直す（理解なし）
✅ 翻訳: コードを読む → 閉じる → 自分の言葉で書く
```

同じ機能を、**自分のスタイルで**書き直す。
変数名も、構造も、自分で決める。

---

## 6. 具体的な学習プラン（Mashiroを題材に）

| 週 | テーマ | やること | ゴール |
|----|--------|----------|--------|
| 1 | WebSocket | 自分でWS通信を実装（ライブラリなし） | プロトコルを説明できる |
| 2 | LLM API | HTTPリクエストを手で書く | APIの仕組みを理解 |
| 3 | 非同期処理 | asyncioの仕組みを理解、自分で書く | イベントループを説明できる |
| 4 | LoRA | 行列演算の基礎 | なぜLoRAが効率的か説明できる |
| 5 | Transformer | Attention機構を手で実装 | Self-Attentionを説明できる |

---

## 7. 料理人のメタファー

```
材料は買ってくる（ライブラリ、フレームワーク）
    ↓
でも調理は自分でする（コードを書く、設計する）
    ↓
レシピの意味を理解している（なぜこう書くのかわかっている）
    ↓
これが「自分の料理」と言える条件
```

---

## 8. 学習の記録

### 理解したことを書き留める

各学習後に以下を記録：

1. **何を学んだか**（概念、技術）
2. **なぜそうなっているか**（理由、背景）
3. **自分の言葉での説明**（他人に教えるように）
4. **疑問点**（まだわからないこと）
5. **関連する概念**（次に学ぶべきこと）

---

## 9. 心構え

- **時間がかかっても良い** - 理解には時間がかかる
- **完璧を求めない** - 70%理解したら次へ進む
- **手を動かす** - 読むだけでなく書く
- **失敗を恐れない** - エラーは最高の教師
- **楽しむ** - 内側からの情熱を大切に

---

## 参考：Vedalの例

Vedalも独学（YouTubeで学んだ）。

**ビジョン → 学習 → 実装 → 理解 → 応用**

このサイクルを回し続けることが成長の鍵。
